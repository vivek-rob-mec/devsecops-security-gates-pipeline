# Threat Modeling

Threat modeling asks what can go wrong before implementation is complete.

Minimum workflow:

1. Draw trust boundaries and data flows.
2. Identify assets and identities.
3. Enumerate threats (for example STRIDE).
4. Rank risk.
5. Choose controls.
6. Track controls as engineering requirements.
7. Revisit the model when architecture or trust boundaries change.
